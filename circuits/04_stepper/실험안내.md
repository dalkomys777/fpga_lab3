# 스텝모터 위상 제어

Icarus: LAB3_STEPPER_PASS checks=8. 종료 831 ns.
RTL과 XDC는 매뉴얼에 따릅니다. TB 리셋 해제만 하강 에지(40 ns)로 옮기고 검사 로그를 추가했습니다.
아래 시각은 현재 TB 기준입니다. Vivado 검증과 실제 모터 구동은 아직 수행하지 않았습니다.

## 실행
- 04_stepper - 02 Simulate
- 04_stepper - 03 Open waveform

## 파형 신호
- tb_stepper: clk_50mhz, rst_p, enable, direction, stepmotor
- dut: enable_sync, direction_sync, state, count
stepmotor는 Binary, state/count는 Unsigned Decimal로 표시합니다.

## 주요 예상값 (상승 에지 후 1 ns 검사)
| 시각 | 조건 | state | stepmotor |
|---|---|---:|---|
| 41 ns | 초기화 확인 | 0 | 0011 |
| 151 ns | 정방향 1단계 | 1 | 0110 |
| 231 ns | 정방향 2단계 | 2 | 1100 |
| 311 ns | 정방향 3단계 | 3 | 1001 |
| 391 ns | 정방향 순환 | 0 | 0011 |
| 471 ns | 역방향 1단계 | 3 | 1001 |
| 551 ns | 역방향 2단계 | 2 | 1100 |
| 591~831 ns | enable_sync=0, 정지 유지 | 2 | 1100 |

STEP_CYCLES=8/2=4이며 20 ns 클록 기준 단계 간격은 80 ns입니다.
실제 상태 변화는 표의 단일 검사 시각보다 1 ns 앞선 상승 에지에서 발생합니다.
enable은 551 ns에 0으로 바뀌고 enable_sync는 590 ns에 0이 됩니다.
정지 시 출력은 0000으로 꺼지지 않고 마지막 패턴을 유지합니다.
증빙은 evidence/04_stepper/icarus_baseline에 저장했습니다.

## STEP_HZ 수정 및 복구
TB의 STEP_HZ를 2에서 1로 변경하고 기존 검사 조건은 유지했습니다.
수정 검사 시각(ns): [41, 231, 391, 551, 711, 871, 1031, 1311]
복구 검사 시각(ns): [41, 151, 231, 311, 391, 471, 551, 831]
단계 간격은 수정 후 160 ns, 복구 후 80 ns로 확인했습니다.
TB는 상태 도달을 기다린 뒤 출력 패턴을 검사하므로 수정 후에도 checks=8로 PASS합니다. 고정 시각이나 속도를 자동 검사하는 TB가 아닙니다.
실제 모터 회전 속도는 아직 관측하지 않았습니다.
증빙은 evidence/04_stepper/step1_modified 및 step2_restored에 저장했습니다.
