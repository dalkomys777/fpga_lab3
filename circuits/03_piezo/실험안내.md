# 피에조 단일 음 회로

RTL/XDC는 매뉴얼 기준입니다. Icarus에서 LAB3_PIEZO_PASS edges=5를 확인했습니다.
종료 시각은 551 ns입니다. 실제 보드 음 출력과 Vivado 검증은 아직 수행하지 않았습니다.

## 테스트벤치 조정
리셋 해제를 60 ns의 하강 에지로 옮겨 상승 에지 처리와의 경합을 방지했습니다.
매뉴얼의 piezo와 dut.piezo 비교는 같은 신호끼리의 비교이므로 출력 미정값이나 잘못된 출력을 검출하지 못합니다.
대신 매 클록에서 고정 기대값 ((cycles/5)%2)와 출력을 case inequality로 비교합니다.
내부 카운터가 아닌 실제 출력의 변화를 검출하여 반전 간격 5클록 및 총 반전 횟수 5회를 확인합니다.
반전 시각은 상승 에지 직후이고 로그는 갱신을 기다린 1 ns 뒤에 기록됩니다.

## 실행
Terminal → Run Task... → 03_piezo - 02 Simulate
Terminal → Run Task... → 03_piezo - 03 Open waveform

## 추가 신호
- tb_piezo: clk_50mhz, rst_p, piezo
- tb_piezo.dut: count
- 선택: tb_piezo의 cycles, edges

## 이론에 따른 주요 구간
테스트벤치의 HALF_PERIOD=1000/(2×100)=5클록입니다.
클록 주기는 20 ns이므로 반주기 100 ns, 전체 주기 200 ns입니다.
- 150 ns 이상 250 ns 미만: piezo=1
- 250 ns 이상 350 ns 미만: piezo=0
- 350 ns 이상 450 ns 미만: piezo=1
- 450 ns 이상 550 ns 미만: piezo=0
- 550 ns: piezo가 1로 반전, 551 ns: PASS 후 종료
각 반전 시점에 count=0으로 돌아가며 이후 1,2,3,4를 계수합니다.
실제 보드는 50 MHz 및 TONE_HZ=294를 사용하므로 테스트벤치의 200 ns 주기와 구분해야 합니다.

## 증빙
상위 evidence/03_piezo/icarus_baseline에 PASS 로그, VCD, 입력 해시와 TB를 저장했습니다.

## 주파수 파라미터 수정 및 복구
TB 인스턴스의 TONE_HZ만 100에서 50으로 변경하고 기대값은 유지했습니다.
반주기 계산값은 5클록(100 ns)에서 10클록(200 ns)으로 늘어납니다.
151 ns의 cycle=5 검사에서 expected=1, piezo=0으로 실패했습니다. 이 실행은 첫 불일치에서 종료되므로 변경된 전체 주기를 관측한 결과는 아닙니다.
TONE_HZ=100으로 복구 후 551 ns에서 LAB3_PIEZO_PASS edges=5를 확인했습니다.
수정 로그 및 파형은 evidence/03_piezo/tone50_modified, 복구 증빙은 tone100_restored에 보관했습니다.
실제 보드의 기본 TONE_HZ=294는 변경하지 않았으며 소리 변화는 아직 관찰하지 않았습니다.
