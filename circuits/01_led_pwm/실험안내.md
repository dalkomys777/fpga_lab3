## 동작 원리
실제 회로는 50 MHz 클록을 사용합니다. PWM 주파수는 1 kHz이므로 한 주기는 50,000클록(1 ms)입니다.
버튼을 누를 때마다 level이 0에서 10까지 증가하고 다시 0으로 돌아갑니다.
HIGH 클록 수는 50,000 × level / 10입니다. level=3이면 15,000클록(0.3 ms) 동안 HIGH입니다.
버튼 디바운스는 1,000,000클록으로 20 ms입니다.

테스트벤치는 PWM 주기를 10클록, 디바운스를 2클록으로 줄여 검사합니다.
테스트벤치의 클록 주기는 여전히 20 ns이므로 파형의 PWM 주기는 200 ns입니다.
CLK_HZ=1000은 빠른 테스트를 위한 계산 파라미터이며 테스트벤치 클록이 실제로 1 kHz라는 뜻은 아닙니다.

## 실제 Icarus 결과
| 조건 | 한 주기 HIGH 기대값 | 측정값 |
|---|---:|---:|
| 리셋 후 0% | 0/10 | 0/10 |
| 버튼 3회 후 30% | 3/10 | 3/10 |
| 버튼 총 10회 후 100% | 10/10 | 10/10 |
| 다음 버튼 후 0% 복귀 | 0/10 | 0/10 |

이 네 검사는 led[0]의 HIGH 클록 수를 확인합니다. 모든 밝기 단계와 버튼 바운스의 모든 경우를 포괄한 검사는 아닙니다.

## 매뉴얼 코드와의 차이
RTL과 XDC의 내용은 매뉴얼 그대로입니다.
테스트벤치에서는 버튼 전환 및 리셋 해제 시점을 하강 에지로 옮겼습니다. DUT의 상승 에지 처리와 입력 변경 사이의 실행 순서 경합을 피하기 위함입니다.
HIGH 개수의 기대값과 4개 검사 조건은 유지하고, 각 검사의 기대값·측정값·시각 출력을 추가했습니다.

## VS Code에서 실행
상위 LAB3.code-workspace를 연 상태에서 Terminal → Run Task...를 선택합니다.
1. 01_led_pwm - 01 Check tools
2. 01_led_pwm - 02 Simulate
3. 01_led_pwm - 03 Open waveform

이 PC에서 사용 가능한 Python 실행 경로를 통합 작업 영역과 첫 회로 작업 영역에 지정했습니다.
다른 PC로 이동하면 windows.command의 Python 경로를 해당 PC에 맞춰 변경해야 합니다.

파형이 텍스트로 열리면 탭 우클릭 → Reopen Editor With... → VaporView를 선택합니다.
파형에서 clk_50mhz, rst_p, button, led와 dut 아래 press, level, u_pwm.count, u_pwm.pwm을 추가합니다.
Zoom Fit으로 전체 구간을 확인하고 30% 구간을 확대해 10클록 중 HIGH가 3클록인지 봅니다.
시뮬레이션 PASS 터미널과 파형 화면을 보고서 증빙으로 캡처합니다.

원본 실행 로그와 VCD는 상위 evidence/01_led_pwm/icarus_baseline에 보관했습니다.
다음 단계는 파형 확인, LEVELS 수정/복구 실험, 예비보고서 정리입니다.
